# Android版

Java + AppCompatのネイティブアプリです。WebViewやJavaScriptブリッジはありません。暗号化したノートと画像を端末のアプリ専用領域に持ち、PCが停止していても閲覧・編集できます。

## 2.1.0 のツリー・表示設定

- ノートブック → セクション → 記事のツリーをタップで開閉します。検索時は一致する記事の親分類を開いて表示します。
- 行の文字部分を長押ししてドラッグすると、分類への移動や並べ替えができます。記事を分類へ落とすと移動、行の上半分／下半分へ落とすと前／後へ並べ替えます。ノートブック同士、同一ノートブック内のセクション同士も並べ替えできます。
- 行の「⋮」から移動先を選ぶ方法、「上へ移動／下へ移動」も使えます。削除済み・競合中の記事は移動を拒否します。
- 「分類＋」で空の分類を作成できます。各分類の「⋮」→「この場所に新しい記事」でその場所に記事を作成します。
- セクションの「⋮」→「セクション名を変更」で所属記事をまとめて改名します。本文・画像・履歴・並び順を保持し、削除済み・競合版も状態を維持して更新します。同じノートブック内の既存名との結合は行いません。
- 記事の分類変更・改名はLAN同期します。並び順・空の分類・開閉状態は各端末の `navigation.enc` に暗号化保存し、端末間で同期しません（Windows側も同じ方針）。
- 「設定」→「表示・文字サイズ」で画面全体のサイズ（6〜48sp）と標準／明朝／等幅フォント、本文だけの倍率（50〜300%）を変更できます。ツリー・ボタン・入力欄・設定画面に即時反映し、次回起動時も保持します。Android自体の文字倍率も適用されます。表示変更で本文や画像を再取得しません。

Windowsのウィンドウ位置・サイズ保存とDPAPI自動解除はWindows専用です。Androidは画面構成をOSが管理し、従来の指紋・端末認証を維持します。

## インストールと初回接続

署名付き `dist/TwoNote.apk` をAndroid 8以降の端末にインストールしてください。

### 2.2.2：表・グラフの下書きと保存互換性

表・グラフの入力中は、見出し・種類・未完成のCSV・編集元の版・挿入位置を `block-draft.enc` に暗号化して退避します。他アプリへの切替・画面再作成・再起動後は、保管庫のロック解除後に続きを開きます。入力途中でCSVや数値の形式が不完全でも下書きは保持します。戻る操作では下書きを残し、「下書きを破棄」で明示的に捨てられます。新しい表を開く際に別の下書きが残っていれば、再開・破棄を選択します。

正式な保存後は下書きを片付け、保存直後の終了で同じ表が二重に追加されないようにします。同期などで元の記事に別の変更が届いていた場合は、編集開始時の版から分岐させ、両方を保持します。通常本文の下書きとは別のファイルで、端末内だけの退避です。下書き自体はLAN同期・通常バックアップの対象ではありません。本文や表の入力、保管庫鍵をActivityの保存Bundleへ書き込みません。

下書きの上限は8MB（入力は100万UTF-16単位、見出しは4096単位）です。容量不足・権限・上限超過などで端末へ退避できない場合は警告し、同じアプリ実行中の暗号化メモリ退避を試みます。この場合、強制終了後の復元は保証できないため、空き容量を確保して保存してください。

表・グラフの正式データはWindowsと共通でUTF-8の2MBまでです。全角数字・アンダースコア区切りは共通の10進数へ正規化し、旧版由来のJava数値形式も読込時に救済します。Windowsも対応版へ更新してください。

### 2.2.1：削除した競合版の表示修正

削除済みの編集版を通常のツリーと競合数から除外します。旧版ですでに削除した版にも適用されます。残った版の移動・並べ替えも可能です。設定で削除済み表示をオンにすれば内容を確認でき、「その他」から復元できます。

残す版を開き「その他」→「この版を採用」で、内容を混ぜずにその版だけを採用できます。統合時も、削除済みの本文・添付は混ぜません。いずれも元の変更履歴は保持し、確認中に別端末の編集が届いた場合は自動確定せず再確認を求めます。後から届いた新たな編集は競合として残します。Windowsも対応版に更新してください。

### 2.2.0：本文内の画像・表・グラフ

本文のカーソル位置に「添付」から写真・撮影画像・表・棒グラフ・折れ線グラフを挿入できます。写真選択・撮影中にロックや画面再作成が起きても挿入位置を保持します。画像・表は本文中で選択し、同じ記事内の切り取り・貼り付けで移動できます。「添付の管理」から再挿入・拡大表示・表やグラフの元データ編集ができます。

表はカンマ／タブ区切りの最大50行×12列、グラフは項目名,数値の最大30行（見出し行不要）です。表示に収まらないセル文字は省略しますが、編集データは保存されます。数式の実行はしません。元データも保管庫内に暗号化保存し、WindowsとのLAN同期に含めます。画像の本文からの削除では添付そのものは削除せず、再挿入可能です。「この添付を外す」では本文内の参照も外します。

従来の位置情報がない画像は本文末尾に表示し、編集保存時に位置情報を記録します。原本からの順序復元はWindows側の再取り込みで行います（未編集の本文・一致する添付に限定）。OneNoteの自由配置や、グラフ画像から数値を逆算する機能はありません。Windowsも対応版に更新してください。古いアプリでは本文内参照が文字表示になります。プレビューは記事表示時に端末内で作成し、入力のたびに画像を読み直しません。

### 2.1.3：写真の選択とカメラ撮影

記事の「添付」から「写真を選ぶ」「カメラで撮影」「ファイルを選ぶ」を選択できます。

- 写真の選択にはAndroid標準の写真選択画面を使います。未対応の端末では画像限定のファイル選択に切り替えます。端末内の写真全体へのアクセス権限は要求せず、選んだ1枚だけを取り込みます。元の写真は変更・削除しません。
- カメラ撮影は端末のカメラアプリを起動します。初回はカメラ権限を確認します（QR読取でも同じ権限を使用）。小さなサムネイルではなく撮影ファイルを取り込み、1ファイル64MBまでです。
- 撮影の受け渡し中〜保管庫への取り込み完了までは、アプリ専用の内部キャッシュに**未暗号化の一時写真**を置きます。カメラには対象ファイルだけを一時的に許可し、結果が戻ると権限を取り消します。写真ライブラリへの登録や外部の共有フォルダへの保存はTwoNoteからは行いません。ただしカメラアプリ自身の保存・バックアップ動作までは制御できません。
- 保管庫へ取り込んだ写真は他の添付と同様に暗号化し、その後に一時写真を削除します。撮影中止時も削除します。取り込み失敗時は再試行のため一時写真を保持し、「添付」から再試行・取り消しできます。復元対象のない一時写真は次のアプリ起動時に削除します。削除失敗時は警告します。
- カメラ等への切り替えでアプリがバックグラウンドへ移った場合、既存通り保管庫をロックします。戻って解除すると元の記事へ追加します。画面再作成時も添付先と撮影ファイルの参照だけを復元し、保管庫鍵や写真データを画面の保存状態に含めません。OSによるキャッシュ削除やアプリの強制終了では、再撮影が必要な場合があります。
- カメラの縦横・反転情報（EXIF）をプレビューに適用します。写真の元データ・EXIF情報は保持されるため、位置情報等が含まれていれば暗号化された添付にも残ります。2.1.3では添付欄への追加でしたが、2.2.0以降は本文中のカーソル位置へ挿入します。

LAN同期の形式は変更していません。Windows版を作り直さず、既存のWindows版へ写真付き記事を同期できます。写真の選択・実カメラのメーカー依存動作は実機確認が必要です。

設計根拠：[Androidの写真選択](https://developer.android.com/training/data-storage/shared/photo-picker)、[FileProviderによる一時的なファイル共有](https://developer.android.com/reference/androidx/core/content/FileProvider)。

### 2.1.2：保存失敗・画面再作成への対応

通常保存できない編集は保管庫内の `draft.enc` へ暗号化して退避し、別プロセスで開き直しても復元します。保管庫と同じ鍵を使い、ロック中に本文は読めません。保存済みの下書きを誤って再適用せず、同期で別の編集が届いていた場合は変更履歴を分岐させて双方を保持します。下書きは16MBまでで、容量不足等により退避にも失敗した場合は警告します。下書きは同期・通常のバックアップ対象には含めず、正式な保存が成功するまで保持します。

ファイル選択時は記事リビジョン・保管庫ID・選択URIだけをActivityの保存状態に保持します。本文や保管庫鍵は保存状態に含めません。AndroidがActivityを再作成しても選択結果を元の記事に戻し、対応するプロバイダーのURI権限は取り込み完了後に解放します。

破損したツリー表示設定は暗号化状態のまま退避して再生成します。通常保存の検証は新規変更の親・添付・循環に限定し、保管庫を開く際には全履歴を検証します。暗号化形式とWindowsとの同期形式は変更していません。

PCで同期待受を開始し、AndroidでQRを読み取り、保管庫のパスワードを入力します。その後、設定から指紋・端末認証を有効にできます。端末の認証でAndroid Keystore内の鍵を使用して保管庫鍵を取り出す構成であり、パスワードそのものは保存しません。認証解除にPCへの接続は不要です。

### 2.1.1：指紋登録時の暗号処理を修正

認証完了前にAES-GCMの `updateAAD` を呼んでいた処理を、認証成功後の保存・復号時へ移しました。Android Keystoreが認証前の処理エラーを保持し、指紋認証後の `doFinal` で `IllegalBlockSizeException` を返す経路を修正しています。認証強度とAES-GCM、保管庫に結び付けるAADは維持します。

再登録は別の候補鍵を作成し、認証と暗号化した設定の保存が成功した後に切り替えます。中止・失敗で旧登録を先に削除しません。認証用の鍵が消えている場合は復号時に新しい鍵を勝手に作らず、パスワードで開いてから再登録を案内します。Androidの認証可否チェックと、失敗段階・例外の原因を表示する診断情報も追加しています。

既存アプリをアンインストールせず2.1.1を上書きし、パスワードで開いて「設定」→「指紋・端末認証を設定」をやり直してください。ノートの削除・再同期・保管庫パスワードの変更は不要です。端末固有の認証動作は実機確認が必要です。

設計根拠：[Androidの認証付き暗号処理](https://developer.android.com/identity/sign-in/biometric-auth)、[KeystoreのAADエラー保持処理](https://android.googlesource.com/platform/frameworks/base/+/78a3fdfbed02ccfaaf917fb1dc4c5bb37f26496b/keystore/java/android/security/keystore2/AndroidKeyStoreCipherSpiBase.java)。

Android 11以降は強い生体認証または画面ロック、Android 8〜10は強い生体認証に対応します。利用できない端末はパスワードで開けます。アプリがバックグラウンドに移ると編集を保存してロックし、画面・鍵・画像を片付けます。

同期は手動操作だけです。受信したノートが変化し、未保存の入力がない場合に限って表示を更新します。通常時の再取得や待受はありません。証明書はQRに入っているSHA-256値と一致するものだけを受け付け、AndroidへのCA証明書登録は不要です。

## ビルドとテスト

```powershell
.\tools\bootstrap_android.ps1 -AcceptSdkLicense
.\android\build_android.ps1
.\tools\test_android_core.ps1
.\tools\test_android_ui.ps1
```

ビルドはプロジェクト内JDK 21 / Gradle 8.9 / Android SDK 35を使います。releaseビルドでlintとAPK署名検証も実行します。初回に `.tools/signing` へ署名鍵を生成し、そのパスワードをWindows DPAPIで保護します。以後のアップデートには同じ署名鍵が必要なので紛失・公開しないでください。DPAPIのファイルは同じWindowsユーザー環境に結び付いています。

`-DebugBuild` を付けると `dist/TwoNote-debug.apk` を作成します。debug版とrelease版は署名が異なるため、そのまま上書きできない場合があります。アンインストールすると端末内ノートも消えるため、先にPCへ同期・バックアップしてください。

急ぎの場合の `-SkipLint` は追加の完全lintを省略します（Android標準のrelease必須チェックと署名検証は残ります）。ビルドは1ワーカーで実行します。ソースに変更がない増分ビルドではAPKが再利用されるため、出力の `UP-TO-DATE` とAPKのハッシュで判別してください。

RobolectricでAndroid 9・15相当の保存・ロック・競合処理を検証します。また、実際のJava保存・同期コードをJVM上でPython版と通信させて形式互換性を確認します。生体認証のハードウェア・メーカー独自のライフサイクル・実LAN通信は実機での確認が必要です。Robolectricは実機テストの代替を保証するものではありません。

OSのクラウドバックアップ・端末間自動転送を無効化しています。ノートの移動はTwoNoteの同期で行ってください。
