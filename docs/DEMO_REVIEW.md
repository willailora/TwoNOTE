# ダミーデータでの確認・スクリーンショット

レビューや公開用のスクリーンショットは、専用のダミー保管庫を明示的に指定して行ってください。通常の起動では既存のデータ保存先を検出する場合があるため、確認用の起動では必ず `--data-dir` を指定します。

## ダミー保管庫の作成

依存関係の導入後、公開用フォルダから次を実行します。ダミー専用のパスワードを求められたら、実際の保管庫と共用しない12文字以上のものを設定します。例の `demo-only-password` はダミー用途だけに使ってください。

```powershell
$demoRoot = Join-Path ([IO.Path]::GetTempPath()) ('TwoNote-demo-' + [Guid]::NewGuid().ToString('N'))
python -B tools/create_demo_vault.py --output "$demoRoot"
python -B desktop.py --data-dir "$demoRoot"
```

この操作は実際にGUIを起動します。確認担当者が必要なときに実行してください。ビルド済みのEXEを使う場合も、同じ `--data-dir "$demoRoot"` を指定します。

生成物は、合成した日本語記事、コードで描いたDEMO画像、表・棒グラフ・折れ線グラフ、取り込み確認用の `exports/demo.mht` です。既存のノートや写真は読み取りません。公開用フォルダの中への生成、既存フォルダの上書きは拒否します。生成した保管庫やMHTをリポジトリへコピーしないでください。

## 確認する画面と操作

- ロック画面、ダークモードのツリー、日本語・絵文字、フォントサイズ変更。
- 本文中のDEMO画像、表、棒グラフ・折れ線グラフ。表のデータを変更して保存・再起動後に保持されること。
- メニューから `exports/demo.mht` を取り込み、本文・画像・表・表の説明文を確認すること。これは合成したMHTの確認であり、実際のOneNote原本すべての再現を保証するものではありません。
- Androidも確認する場合、初回同期、オフライン閲覧・編集、写真の追加、表入力中のアプリ切替と復元、指紋・端末認証。

Windowsはダミー保存先を明示し、Androidは確認専用のエミュレーター、別ユーザーなど、実際の保管庫と分離した環境を使います。実データが入っているAndroidアプリを、スクリーンショットのためにアンインストール・初期化しないでください。

## 公開用画像に写すもの

記事名・本文・画像がDEMOデータであることを確認します。実ユーザーの名前、保存先の絶対パス、ファイル選択履歴、通知、パスワード入力内容、同期用QRコードやペアリングコードは写さないでください。デスクトップ全体ではなく、必要なアプリ画面の範囲を撮影します。

公開候補フォルダでは画像ファイルを登録対象にしていません。画像をREADMEへ掲載する際は、撮影内容を確認してから公開する画像だけを別途選んでください。保管庫・鍵・ログなどを画像と一緒に追加しないようにします。
